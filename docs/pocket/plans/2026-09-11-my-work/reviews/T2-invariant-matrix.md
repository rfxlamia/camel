### Confirmed behavior

- **Status precedence is currently aligned.** SQL checks recognized non-null categories before any slot fallback and guards every slot branch with `st.category IS NULL` (`my-work-query.ts:63-73`). Response normalization checks `category != null` first and only reads `slot` when the category is absent (`my-work-response-serialization.ts:40-51`). Thus unknown non-null category plus `slot='done'` is `Other`, while null category plus `slot='done'` normalizes to `completed`.
- **Terminal visibility is currently aligned.** SQL excludes group ranks `2` and `3` from Active (`my-work-data-source-list.ts:69-70,132-134`). Response Active filtering excludes only normalized `completed` and `canceled` (`my-work-response-serialization.ts:64-77`). An unknown non-null category is group `Other`/rank `4`, so it remains visible in Active and All.
- **The response timezone fallback is deterministic.** `my-work-response-pagination.ts:29-45` and `my-work-query.ts:36-54` resolve null/undefined timezone to `UTC`; an invalid timezone catches the formatter error and falls back to the UTC ISO date from `now`. The normal service path supplies a local-date map for every authorized workspace (`my-work-service-list.ts:54-65`), so SQL and response normally receive the same calendar date.
- **Numeric key ordering was repaired and is currently represented consistently.** SQL orders by `key_number` (`my-work-data-source-list.ts:93-95,154-156`), response comparison uses `myWorkCursorKeyNumber` (`my-work-response-pagination.ts:103-109`), and cursor serialization validates the canonical key plus optional numeric `keyNumber` (`:123-166`). The existing test at `server/src/routes/my-work.test.ts:653-712` proves only a two-row `OR-2`/`OR-10` case.
- **Membership, assignment, soft-delete, detail reauthorization, deduplication, and transient failure behavior were covered by the prior review.** The prior artifact `reviews/T2-review.json`, `stage_1.concerns_addressed`, confirms these areas at the current source locations. They remain constraints for the repair and are not the cause of the current block.

### Confirmed cross-layer violation

`sourceOrderExpressions` currently treats only groups `< 2` as overdue (`my-work-query.ts:107-113`). That includes Backlog and Started but excludes group `4` (`Other`). The response path treats every non-completed/non-canceled group, including `Other`, as overdue when its date is before the workspace-local date (`my-work-response-pagination.ts:51-56`). Therefore an unknown non-null category with `slot='done'` and a past due date is response-overdue but SQL-non-overdue.

The cursor predicate compounds the mismatch: for a response cursor with `overdue=true`, `my-work-query.ts:163-168` searches for SQL rank greater than `0` and equal to `0`, although the current SQL assigns the affected `Other` row rank `1`. The first `group=4` predicate can consequently match the beginning of the same Other stream instead of only rows after the cursor. With a bounded source page, this can reread a sentinel window, emit duplicate rows, terminate with an empty page, or leave later Other rows unreachable. This is the exact cycle-5 finding recorded in `reviews/T2-review.json`, `stage_1.issues[0]` and `fix_instructions`.

### Effective tuple notation

Let the intended global tuple be:

`(G, O, N, D, U, W, S, K, I)`

where:

- `G` = normalized status group rank: Backlog `0`, Started `1`, Completed `2`, Canceled `3`, Other `4`.
- `O` = overdue rank: overdue `0`, not overdue `1`.
- `N` = due-date-null rank: dated `0`, null `1`.
- `D` = date ascending.
- `U` = updated time descending.
- `W` = workspace ID ascending.
- `S` = source rank: Board `0`, Tracker `1`.
- `K` = numeric `key_number` ascending.
- `I` = physical row ID ascending.

Each source SQL query orders `(G,O,N,D,U,W,K,I)`; `S` is implicit in the source-specific query and is added to continuation by `appendSourceCursorPredicate`. The response comparator orders the full tuple `(G,O,N,D,U,W,S,K,I)`. The cursor serializes all required values except `N`, which is derived from `dueDate`; it carries both the canonical key string for validation and the numeric key number used for `K`. The only confirmed tuple disagreement is `O` for `Other` rows.

## Minimal Repair Contract

This contract is intentionally limited to the confirmed cross-layer defect and the regression evidence needed to prevent another blind cycle.

1. **Production boundary:** update only `server/src/routes/my-work-query.ts`, specifically the `overdueRank` expression returned by `sourceOrderExpressions` at `:93-125`. Its overdue predicate must use the same normalized terminal definition as response code: a row is overdue when it has a non-null due date before the workspace-local date and its normalized group is not `completed` or `canceled` (group ranks `2` and `3`). The implementation may express this as `group NOT IN (2, 3)` or an equivalent SQL expression, but it must not use the old `group < 2` restriction.
2. **Preserve status precedence:** do not alter the cycle-4 rule in `statusGroupExpression` or `normalizeMyWorkStatusCategory`. A non-null unknown category must remain group `Other` even when `slot='done'`; slot fallback remains legal only for null/undefined category.
3. **Preserve cursor mapping:** retain the existing rank mapping used by `sourceCursorPredicate` (`overdue=true` means SQL rank `0`, `overdue=false` means SQL rank `1`) once SQL rank semantics are corrected. Do not solve the mismatch by changing response overdue semantics or by treating unknown+done as terminal.
4. **Regression boundary:** extend `server/src/routes/my-work.test.ts` with R1-R5, at minimum the timezone/Other SQL capture and the 73-row, multi-page, no-gap/no-duplicate regression. The test must observe both generated SQL and the serialized response; a response-only in-memory comparator test is insufficient.
5. **Test-double boundary:** query-capture tests must use parameterized Kysely SQL and assert the generated order/predicate/limit. Service tests may inject source rows and hydration, but injected doubles must not implement or mock merge, status normalization, overdue classification, or pagination.
6. **No unrelated changes:** do not modify `server/src/routes.ts`, detail reauthorization, existing Board/Tracker routes, the shared legacy serializer contract, schema/migrations, client code, SSE, mutations, search behavior, or the prior `T2-review.json` artifact. No new status category, projection, or unbounded query is authorized.

## Open Uncertainties

1. **Cursor stability across a local midnight:** the cursor encodes the computed overdue boolean but not the workspace-local date or a snapshot timestamp. If page 1 is read before local midnight and page 2 after it, an item can change from not overdue to overdue and move before the cursor. The approved spec defines refresh-time overdue behavior but does not define cursor snapshot semantics. The bounded repair should use one fixed `now` per request and document this boundary; adding a snapshot to the API requires a separate decision.
2. **Missing local-date map at the low-level data-source API:** the normal service path always supplies `workspaceLocalDates`, but direct callers can omit it and cause `localDateExpression` to use database `CURRENT_DATE`. Whether the low-level function should reject an incomplete map or retain this fallback is unspecified. The repair should not change it silently; tests must provide the map when asserting SQL overdue behavior.
3. **Malformed timezone policy:** the current implementation deterministically treats null/undefined and malformed timezone values as UTC-date fallback in both service and response helpers. The approved spec requires timezone-aware behavior but does not say whether malformed persisted values should be rejected instead. This repair contract pins the existing UTC fallback for compatibility; changing that policy requires product/schema guidance.
4. **Tracker-wins with independently bounded source windows:** `mergeMyWorkRows` can only suppress a Board row when the corresponding Tracker row is present in the fetched Tracker window. The packet requires bounded per-source queries but does not specify how to guarantee cross-source dedup when the higher-priority row sorts outside that window. R6 should expose the edge if it is reachable; resolving it may require a source-union/query-shape decision beyond the confirmed overdue fix.
